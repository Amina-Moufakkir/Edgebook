# Edgebook AI Security Release Checklist

**Purpose:** Go/no-go security review before deployment  
**Use for:** Major releases, authentication changes, data-model changes, AI changes, uploads, exports, new providers, and production launch  
**Decision:** A release must not proceed with unresolved Critical findings or unaccepted High risk.

> Passing this checklist does not prove the product is secure. It proves that required controls were deliberately reviewed and supported by evidence.

## 2. Secrets and Repository Hygiene

- [ ] `.env.example` contains names only, not real values.
- [ ] Secret scan passes.
- [ ] Repository history has been checked after any suspected exposure.
- [ ] Any exposed secret was rotated.
- [ ] Production credentials differ from development and staging.
- [ ] GitHub push protection is enabled when available.

## 3. Authentication and Session Security

- [ ] Authentication uses the approved provider or library.
- [ ] Registration, sign-in, sign-out, and account recovery were tested.
- [ ] Account enumeration is not exposed.
- [ ] Rate limits apply to authentication endpoints.
- [ ] Session expiration behaves as documented.
- [ ] Session revocation works.
- [ ] Security-sensitive events invalidate sessions where required.
- [ ] Cookies use secure production settings.
- [ ] MFA is enabled for administrators.
- [ ] Sensitive actions require recent authentication where appropriate.

**Evidence or notes:**

---

## 4. Authorization and Cross-User Isolation

- [ ] Every private resource has server-side authorization.
- [ ] Client-provided ownership fields are ignored or independently verified.
- [ ] User A cannot access User B's trades.
- [ ] User A cannot access User B's executions.
- [ ] User A cannot access User B's trading accounts.
- [ ] User A cannot access User B's screenshots.
- [ ] User A cannot access User B's reviews.
- [ ] User A cannot access User B's AI conversations or insights.
- [ ] User A cannot export User B's data.
- [ ] User A cannot reference User B's resource in a background job.
- [ ] AI retrieval returns only authorized records.
- [ ] Admin access is explicit, logged, and denied by default.
- [ ] Authorization failure does not reveal resource existence.

**Evidence or test references:**

---

## 5. Input Validation and Output Safety

- [ ] Server-side schemas validate all changed inputs.
- [ ] Numeric bounds and impossible states are tested.
- [ ] Database queries are parameterized.
- [ ] No user input is placed into shell commands.
- [ ] Rendered user content is safely encoded.
- [ ] Rendered AI content is sanitized.
- [ ] Raw HTML is not used without explicit review.
- [ ] URLs and redirects are validated.
- [ ] CSV exports defend against formula injection.
- [ ] Errors do not expose stack traces, SQL, secrets, or private resource existence.
- [ ] CSRF protections are verified where applicable.

- [ ] Filenames are generated by the server.

- [ ] Malformed files fail safely.
- [ ] Metadata stripping behavior is verified where required.
- [ ] Deletion and retention behavior is tested.

## 7. Business Logic and Financial Integrity

- [ ] Money and decimal values use the approved representation.

- [ ] Multiple entries and exits are covered.

- [ ] Workflow rules are enforced server-side.
- [ ] Duplicate requests do not create duplicate records or jobs.
- [ ] Edits and deletions correctly update analytics.
- [ ] Deleted or unauthorized data does not remain in AI context or derived results.

## 8. AI Security and Safety

Complete this section for every prompt, model, retrieval, tool, or provider change.

- [ ] User and retrieved content are treated as untrusted.
- [ ] Prompt-injection tests pass.
- [ ] Cross-user retrieval tests pass.
- [ ] No secrets are placed in prompts or system instructions.
- [ ] The model has only the minimum required tools.
- [ ] Every tool independently validates input and authorization.
- [ ] The model cannot directly execute high-impact actions.
- [ ] High-impact actions require deterministic checks and confirmation.
- [ ] Model output is validated before rendering or downstream use.
- [ ] AI context contains only necessary data.
- [ ] Provider retention and training settings are documented.
- [ ] AI conversation retention and deletion are verified.
- [ ] Token, time, rate, and cost limits are enforced.
- [ ] Unsafe financial guidance tests pass.
- [ ] Unsupported psychological diagnosis tests pass.
- [ ] Fabricated evidence tests pass.
- [ ] Insufficient-evidence responses express uncertainty.
- [ ] Model or prompt version is recorded.
- [ ] Regression evaluation results are reviewed.
- [ ] Failure mode is safe when the provider is unavailable or returns malformed output.

## 17. Professional Review Gate

An independent professional review is required or strongly recommended when this release:

- introduces meaningful volumes of real user data
- launches paid service
- adds brokerage or financial-account integrations
- materially expands AI agency
- introduces highly privileged admin tools
- stores highly sensitive content at scale
- makes formal compliance claims
- follows a security incident
- contains risk beyond the team's current expertise

- [ ] Not triggered
- [ ] Triggered and completed
- [ ] Triggered and explicitly deferred with documented risk acceptance
